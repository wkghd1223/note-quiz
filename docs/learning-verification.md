## 브라우저 자동 검증

실행 예:

```sh
PLAYWRIGHT_MODULE=/tmp/note-quiz-qa-tools/node_modules/playwright \
BROWSER_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
UI_BASE_URL=http://localhost:3001 node scripts/verify-practice-ui.cjs
```

설치된 Chrome의 별도 headless 프로필을 사용했다. 사용자 Chrome 탭을 조작하지 않았다. 리더보드 GET/점수 POST는 fixture이며 운영 DB에 점수를 쓰지 않았다. 피드백/제한시간에는 가상 시계, 저장소/오디오 오류에는 API 대체를 사용했다. 실제 청취나 물리적 모바일 기기의 증거로 취급하지 않는다.

최종 실행은 **기능/반응형/모의 광고 15항목 통과**, 실제 광고 관찰 **2항목 미관찰**, 앱 오류/검증 경고 0개다. 결과는 `/tmp/note-quiz-learning-qa/report.json`, 로그는 `/tmp/note-quiz-learning-qa-final.log`에 있다.

## 광고: 실제 관찰과 모의 검증 구분

실제 Chrome에서 Grow house 광고가 표시될 때, 설정 카드 자체의 sticky 위치와 그 아래 Journey sidebar 광고가 겹치는 현상을 재현했다. 설정 카드의 sticky만 제거하고 기존 aside/광고 anchor는 유지했다. 공개 광고 wrapper의 실제 기하를 읽어 외부 사이드·하단 공간 및 모달 공간을 예약한다. 하단 광고 영역을 제외한 연습 스크롤 영역에 공통 푸터를 포함해 마지막 조작도 접근할 수 있도록 했다. 광고 스크립트나 iframe 내부를 변경하지 않았으며 컨트롤을 광고 위에 덮지 않았다.

앞선 데스크톱 실행에서 실제 Grow house 하단 소재와 모달/스크롤 중 조작부를 확인했다. 스크린샷은 `/tmp/note-quiz-learning-qa/desktop-live-house-ad-modal.png`, `desktop-live-house-ad-scroll.png`에 보존돼 있다. sidebar 수정 전후 기하 기록은 `/tmp/note-quiz-live-ad-before.json`, `/tmp/note-quiz-live-ad-after.json`이다. 마지막 전체 실행에서는 모바일·데스크톱 소재가 모두 나타나지 않았으므로 최종 JSON은 두 항목을 `not_observed`로 기록했다.

이후 최종 소스로 가상 시계 없이 별도 관찰하여 **390×844와 1440×900 모두 실제 Grow house 소재가 표시된 상태**를 확인했다. 각 5개 스크롤 위치에서 주요 조작부의 중심/네 모서리 광고 가림은 0개였고, 실제 하단 광고와 대화상자가 겹치지 않았다. 데스크톱은 sidebar 300×250와 하단 728×90 소재가 동시에 표시됐다. 모바일 폭에서는 하단 wrapper 390×90이 표시됐다. 별도 원본 기록은 `/tmp/note-quiz-final-live-house-ad.json`, 스크린샷은 `/tmp/note-quiz-learning-qa/{mobile,desktop}-final-live-house-ad-{scroll,dialog}.png`다. 마지막 전체 runner의 미관찰 상태를 덮어쓰지 않고 이 후속 실제 관찰을 구분해 보존했다.

합성 wrapper 검증과 실제 house 소재 관찰은 각각의 근거다. 이 검사는 데스크톱 Chrome의 모바일 폭 viewport이며 모바일 실기기나 모바일 전용 광고의 증거가 아니다. 유료 소재 전체와 다른 Journey 배치까지 정상이라고 보증하지 않는다. 광고 사업자 설정은 변경하지 않았다.

## Computer use 실제 조작

브라우저 호스트 API는 `browser access host is unavailable` 상태였으나, 사용자의 연결 복구 안내 후 native Chrome 직접 경로로 남은 검증을 수행했다. 다른 창으로 전환되면 URL 보호 검사로 조작을 중단했고 기존 Note Quiz 창을 다시 선택했다. 다른 사이트의 페이지에는 입력하지 않았다.

- Chrome 반응형 UI로 **390×844와 1440×900**을 실제 설정하고 작은 화면, 설정창을 연 채 크기 변경, 실제 Grow 하단 광고와의 분리를 확인했다. 광고 스크립트는 활성 상태였다.
- 모바일 독보 일일 10문제 완료 →원문맥 오답10개 복습 →같은 설정 재시작, 단음 청음10문제 완료 →오답10개 복습 →재시작을 클릭/건반 터치로 확인했다. 독보의 Tab·Enter 건반 입력도 확인했다. 독보는 운영 국가 점수를 제출하지 않는 일일 과제로 조작했다.
- 음정 악보10문제 →오답7개를 다른 시작음으로 복습 →재시작, 높낮이 청음 입문10문제 완료와 예시 재생을 확인했다.
- 코드 악보10문제/오답 복습과 코드 청음10문제/오답10개 복습/재시작을 확인했다. 전위 청음10문제/오답8개 복습/재시작, 조성 기준 진행 청음10문제/오답7개 복습/재시작을 확인했다. 전위·진행 악보도 시작·답변·구성음/정답 비교·중도 종료를 실제 조작했다.
- 결과의 정답 수·정답률·시간 순서, 오답/답변 없음, 복습의 국가 점수 제외, 일반 연습0/10 재시작과 결과 제목 포커스를 확인했다. 반복 터치 중 중복 답안이 늘어나지 않았다.
- 모바일 설정의 초기 닫기 포커스와 Shift+Tab/Tab의 마지막 체크박스↔닫기 순환, Escape 복원, 열린 상태에서 데스크톱으로 전환했을 때 닫힘과 스크롤 사용을 확인했다. 리더보드 티커/직접 링크, 로딩→빈 결과, X·배경·Escape 닫기와 티커 포커스 복원을 확인했다. 조회 실패·재시도와 `role`/`aria-modal` 속성은 자동 브라우저 검증의 별도 근거다.
- 홈의 주요 연습 진입, 공유 링크 설정·예시·사용자 시작 대기, 실제 복사 성공 안내, 새로고침 후 같은 설정의 idle 화면, 일일 완료 표시 유지를 확인했다.
- 독일어 데스크톱과 390×844의 긴 제목/버튼/설정 모달을 확인했다. 종료 후 원래 영어·80% 확대 비율·일반 화면으로 복원하고 검사 도구를 닫았다. 검증 탭은 청음 시작 전 상태로 남겼다.
