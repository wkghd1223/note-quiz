# 멜로디 코드 진행 생성 설계

상태: 설계 단계, 미구현. 기준 코드: `9a9f025`.

조성과 코드 진행을 고르면 각 마디의 코드 구성음으로 단선율 멜로디를 생성한다. 진행은 검토한 패턴 목록에서 자동으로 선택하거나 사용자가 특정 패턴으로 고정한다. 마디 위에는 `C`, `Em`처럼 실제 코드명을 표시한다.

## 합의한 제품 동작

- 조성은 C장조, A단조처럼 으뜸음과 장단조를 함께 선택한다.
- 코드 진행 선택에는 `랜덤`과 등록된 특정 진행을 제공한다. 기본 선택은 `랜덤`이다.
- 랜덤은 선택한 장단조에 맞는 패턴 목록에서 진행 하나를 자동 선택한다. 도수를 임의로 이어 붙여 진행을 만들지 않는다.
- 각 마디의 음표는 해당 코드의 구성음 중에서 선택한다. 연주할 음은 한 번에 하나이며, 동시에 여러 음을 입력하는 화음 연습으로 바꾸지 않는다.
- 코드명은 악보의 각 마디 위에 표시하고 악보와 함께 이동한다.
- 생성된 악보를 읽고 연주한다. 랜덤 선택은 악보를 만들 때 끝나며, 연습 중 정답은 표시된 음표로 고정한다.

## 첫 버전 범위와 설정

기존 자유 생성과 코드 진행 기반 생성을 함께 제공한다. 8마디를 유지하고 한 마디에 코드 하나를 배정한다. 음자리표·음역·박자·템포·음표 길이·점음표·셋잇단음표 설정과 자동 쉼표 규칙을 재사용한다. 코드가 바뀌는 단위는 박자와 관계없이 한 마디다.

| 설정           | 선택 내용                        | 권장 기본값                           |
| -------------- | -------------------------------- | ------------------------------------- |
| 생성 방식      | 자유 생성 / 코드 진행 기반       | 기존 사용자 설정은 자유 생성으로 복원 |
| 조성           | 으뜸음 + 장조 또는 단조          | 신규 설정은 C장조                     |
| 코드 진행      | 랜덤 / 해당 장단조의 등록된 패턴 | 코드 진행 기반 모드에서는 랜덤        |
| 음역·리듬·속도 | 현재 멜로디 설정                 | 기존 값 유지                          |

코드 진행 설정은 코드 진행 기반 모드에서 표시한다. 장단조를 바꾸면 그 모드에 맞는 패턴 목록으로 전환한다. 이전에 고른 고정 패턴이 새 모드에 없으면 `랜덤`으로 전환하고 적용 전에 최종 선택을 보여준다. 으뜸음만 바꾸면 같은 패턴을 새 조성으로 계산한다.

| 사용자 동작             | 진행                      | 음표·리듬           |
| ----------------------- | ------------------------- | ------------------- |
| 랜덤 진행에서 새 멜로디 | 유효한 목록에서 다시 선택 | 새 seed로 다시 생성 |
| 특정 진행에서 새 멜로디 | 선택한 패턴 유지          | 새 seed로 다시 생성 |
| 다시 연습               | 현재 생성 결과 유지       | 현재 생성 결과 유지 |
| 설정 적용               | 적용한 조성·진행으로 확정 | 새 악보 생성        |

랜덤 재선택에서는 같은 패턴이 다시 나올 수 있다. 진행을 고정해도 구체적인 음형은 새롭게 생성한다. 일시정지·재개, 결과창 열기, 화면 크기 변경, 언어 변경은 진행이나 음표를 다시 뽑지 않는다.

## 진행 패턴 목록

장조와 단조의 패턴을 분리하고, 각 항목에 안정적인 ID·표시 이름·장단조·8개의 마디별 코드를 둔다. 아래는 초기 등록 후보이며 음악적 검토와 생성 예시 확인 후 확정한다. 사용자 입력식 진행 편집기는 첫 버전에 포함하지 않는다.

### 장조 후보

| ID                 | 이름        | 1–4마디    | 5–8마디  |
| ------------------ | ----------- | ---------- | -------- |
| `major-basic`      | 기본형      | I–IV–V–I   | I–IV–V–I |
| `major-cycle`      | 순환형      | I–vi–IV–V  | I–IV–V–I |
| `major-two-five`   | ii–V 연결형 | I–vi–ii–V  | I–IV–V–I |
| `major-contrast`   | 변형        | I–V–vi–IV  | ii–V–I–I |
| `major-descending` | 하행 연결형 | I–V–IV–iii | ii–V–I–I |

### 단조 후보

| ID               | 이름   | 1–4마디      | 5–8마디    |
| ---------------- | ------ | ------------ | ---------- |
| `minor-basic`    | 기본형 | i–iv–V–i     | i–iv–V–i   |
| `minor-cycle`    | 순환형 | i–VI–iv–V    | i–iv–V–i   |
| `minor-fifths`   | 연결형 | i–iv–VII–III | VI–ii°–V–i |
| `minor-contrast` | 변형   | i–VI–III–VII | iv–VI–V–i  |

패턴 자체에 마지막 마디와 끝맺음을 포함한다. 생성기가 선택 후 임의로 마지막 코드를 I나 i로 덮어쓰지 않는다. 같은 코드가 두 마디 이어져도 각 마디의 코드명은 표시한다.

## 조성과 코드 계산

조성의 으뜸음·장단조와 보표의 조표를 구분한다. C장조와 A단조는 같은 조표를 쓰지만 코드의 기준음과 진행 목록이 다르다. 단조를 관계장조 이름으로 표시하거나 장조 진행을 그대로 사용하지 않는다.

- 장조는 다이어토닉 3화음을 기준으로 I·ii·iii·IV·V·vi·vii°를 해석한다.
- 단조는 자연단조를 기본으로 하고, 패턴에 명시된 V는 장3화음으로 계산한다. `v`를 추가할 때는 단3화음으로 구분한다.
- 예를 들어 A단조의 `i–iv–V–i`는 `Am–Dm–E–Am`이다. E의 구성음은 E·G♯·B이며 G♯은 조표 밖의 임시표로 표기한다.
- C단조의 V는 G·B·D다. 조표의 B♭을 그대로 사용하지 않고 B♮을 표기해야 한다. 마디 안의 후속 음표도 임시표 유지·취소 규칙과 일치해야 한다.
- MIDI 값뿐 아니라 문자 음이름·변화음·옥타브를 보존한다. 이명동음으로 음만 맞추고 코드나 악보 철자를 바꾸지 않는다.

초기 조성 목록은 현재 표기 모델이 지원하는 단일 올림·내림·제자리표 범위에서 검증해 제공한다. G♯단조의 V처럼 겹올림표가 필요한 경우에는 지원 조성과 이명동음 표기 정책을 구현 전에 확정한다. 지원되지 않는 철자를 묵시적으로 다른 음으로 바꾸지 않는다.

## 음표 생성 규칙

1. 선택한 조성·음역·리듬 설정을 검증한다.
2. 패턴마다 8마디의 실제 코드와 음역 안의 구성음 후보를 계산한다.
3. 랜덤 선택은 모든 코드에 음 후보가 있는 패턴만 대상으로 한다. 고정 패턴에 후보가 없는 코드가 있거나 랜덤 후보가 하나도 없으면 생성 전에 음역·진행 조정을 안내한다.
4. 랜덤이면 유효한 패턴 중 하나를 고르고, 고정이면 지정한 패턴을 사용한다.
5. 기존 리듬 생성으로 각 마디를 채우고, 음표가 들어갈 위치마다 해당 코드의 구성음 후보에서 음을 선택한다.
6. 마디 경계를 포함해 직전 음과 가까운 후보에 높은 가중치를 준다. 코드별 후보 배열의 인덱스가 아니라 실제 음높이 거리를 기준으로 연결한다.
7. 대체 후보가 있으면 같은 음의 과도한 연속 반복을 줄인다. 후보가 하나뿐이면 반복을 허용한다. 매 마디 첫 음을 근음으로 고정하거나 구성음을 오름차순으로만 배치하지 않는다.
8. 완성된 음표·쉼표와 코드 메타데이터를 하나의 악보로 확정한다.

음역은 코드 구성음을 옥타브별로 전개한 뒤 필터링한다. 조표에 있는 음 목록만 필터링하면 단조의 V가 요구하는 G♯ 같은 음을 잃을 수 있으므로, 현재 코드의 실제 철자에서 후보를 계산한다. 일부 구성음이 음역 밖이어도 다른 후보가 있으면 생성할 수 있다. 코드의 모든 구성음을 한 마디에 반드시 한 번씩 연주하게 하지는 않는다. 자동 쉼표는 유지하며, 전체 쉼표 마디에도 배정된 코드는 표시한다.

음역을 임의로 넓히거나 코드 밖의 음으로 빈 후보를 메우지 않는다. 같은 정규화 설정·패턴 목록 버전·seed는 같은 진행과 악보를 만들어야 한다. 진행 선택과 음표 선택은 생성 시 한 번 수행하고 재생 프레임마다 계산하지 않는다.

## 화면과 악보 표시

- 설정의 고정 패턴 선택지는 이름과 도수 진행을 함께 보여준다. 선택 후 요약에서는 해당 조성의 실제 코드명도 확인할 수 있다.
- 각 마디 시작 위에 `C`, `Em`, `F`, `G`처럼 실제 코드명을 표시한다. 단3화음은 `m`, 감3화음은 `dim`으로 구분한다. 예를 들어 A단조의 ii°는 `Bdim`이다.
- 코드명은 실제 렌더러의 마디 또는 시간 본문 시작 좌표에 맞춰 배치한다. 음표 개수나 임의의 고정 간격으로 위치를 추정하지 않는다.
- 코드명은 악보 레일과 함께 이동한다. 마디 전체 쉼표, 박자·조표 변경, 확대·축소, 창 크기 변경, 일시정지와 결과 복기에서도 해당 마디에 붙어 있어야 한다.
- 최근 축소한 음표 배율과 기존 연주선 정렬을 유지한다. 코드명 공간을 별도로 확보해 음표·임시표·보조선과 겹치지 않게 한다.
- 코드명은 안내 정보이며 새로 정답을 고르는 버튼이 아니다. 접근 가능한 악보 설명에도 마디별 코드 정보를 포함한다.

## 채점과 오디오

표시된 단선율의 음정·시작 시점·길이·쉼표를 기존 방식으로 채점한다. 같은 코드의 다른 구성음을 연주해도 표시된 음표와 다르면 오답이다. 코드명과 진행 메타데이터는 별도 입력 대상이나 추가 점수가 아니다.

미리 듣기는 생성된 단선율을 재생한다. 마이크 입력, 카운트인, 오디오 기준 시계, 일시정지·재개·종료·자원 정리는 재사용한다. 코드 반주와 다성 입력 판정은 첫 버전에 포함하지 않는다.

요청한 설정의 `랜덤`과 실제 뽑힌 패턴 ID를 분리한다. 생성된 악보에는 실제 패턴을 보관해 재시도에서 다시 뽑지 않는다. 생성 방식·조성·진행 정보가 악보 ID에 반영되어 서로 다른 설정을 같은 악보로 취급하지 않아야 한다.

저장된 기존 장조 설정은 같은 조성의 자유 생성으로 복원한다. 코드 진행 필드가 없다는 이유로 손상된 설정으로 취급하지 않는다. 기존 화음 맞히기의 문제 목록·선택지, 기본 연습의 동작, 국가 점수 API·DB는 이 기능에서 변경하지 않는다. 새 제품 문구는 현재 지원하는 11개 언어에 함께 반영한다.

## 구현 순서와 완료 조건

1. 장단조별 코드 계산·표기와 초기 패턴 목록을 확정한다. 지원 조성과 겹임시표의 첫 버전 범위를 결정한다.
2. 순수 화성 함수와 설정 검증·저장 데이터 복원을 구현하고 테스트한다.
3. 기존 리듬 생성기에 코드별 음 선택을 연결한다. 동일 seed 재현, 음역과 코드 구성음 준수, 정확한 8마디를 검증한다.
4. 조성·진행 설정과 마디 위 코드명을 연결한다. 새 멜로디·재시도·일시정지·복기에서 같은 악보의 진행이 유지되는지 확인한다.
5. 전체 단위 테스트·TypeScript·lint·production build 후 모바일·데스크톱에서 설정, 미리 듣기, 합성 마이크 연주, 완료·재시도·스크롤을 검증한다.

완료 판단에는 다음 항목을 포함한다.

- 모든 패턴이 8마디이고, 랜덤과 고정 선택이 설정 의미대로 동작한다.
- 생성된 모든 음표가 해당 마디의 코드 구성음이며 선택 음역 안에 있다. 쉼표는 음높이 후보를 소비하지 않는다.
- 음역 후보가 한 개인 경우와 없는 경우가 각각 정해진 동작을 한다.
- 장조·단조, iii·ii°, 단조의 V, 조표 밖 임시표와 이명동음 표기가 정확하다.
- 같은 설정·목록 버전·seed의 결과가 재현되고, 재시도에서 진행·음표가 바뀌지 않는다.
- 코드명이 실제 마디와 함께 움직이고, 기존 음표 배율·연주선 정렬·색상·결과 복기가 유지된다.
- 기존 설정 복원과 자유 생성이 유지되고 기본 연습·기존 화음 문제·국가 점수에 영향이 없다.
- 마이크 검증은 합성 입력과 실제 음성·기기 결과를 구분한다.

## 후속 범위

한 마디 안의 여러 코드, 7화음·차용화음·세컨더리 도미넌트, 경과음·이웃음, 직접 진행 편집, 코드 반주, 화음·보이싱 동시 입력, 코드 구성음이면 자유롭게 연주할 수 있는 즉흥 채점은 별도 설계로 다룬다.
